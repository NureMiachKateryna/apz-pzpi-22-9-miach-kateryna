2. IoT/Smart Device частина системи "HoneyTrack" реалізована як віртуальний пристрій. Концепція полягає у періодичному зборі імітованих даних про мікроклімат, а саме температури та вологості, та їх автоматичному надсиланні на центральний сервер для подальшої обробки, зберігання та аналізу. Пристрій ідентифікує себе унікальним ID та працює автономно, симулюючи поведінку реального фізичного датчика, розташованого в місці зберігання меду.
3. Програмна архітектура віртуального IoT пристрою реалізована у вигляді Node.js скрипта (virtual-iot-device.js). Вона включає наступні логічні модулі:
● Модуль конфігурації: визначення констант, таких як URL сервера, ID датчика, інтервал надсилання даних.
● Модуль симуляції даних: функція (getSimulatedSensorData) для генерації псевдовипадкових значень температури та вологості в реалістичних межах.
● Модуль комунікації: функція (sendData) для формування JSON об'єкта з даними та їх надсилання на REST API сервера за допомогою HTTP POST запиту (використовується бібліотека axios).
● Головний керуючий модуль: функція (runVirtualDevice), що забезпечує періодичний виклик модулів симуляції та комунікації за допомогою setInterval. Також включає попередню перевірку доступності API сервера.

5. IoT пристрій взаємодіє з серверною частиною системи "HoneyTrack" за допомогою REST API через протокол HTTP.
● Метод: POST
● URL ендпоінту: http://localhost:3000/api/sensor-readings
● Формат даних запиту: JSON
● Тіло запиту:
{
"sensor_id": "VIRTUAL_DHT_01",
"value_type": "temperature", // або "humidity"
"value": 22.5
}
6. Для реалізації віртуального IoT пристрою використано:
● Платформа виконання: Node.js
● Мова програмування: JavaScript
● HTTP-клієнт: бібліотека axios для надсилання HTTP POST запитів.
● Робота з JSON: вбудовані можливості JavaScript для створення та серіалізації JSON об'єктів.
● Управління змінними середовища (опціонально для API ключа): бібліотека dotenv
7. Програмна реалізація віртуального IoT пристрою представлена у вигляді Node.js скрипта virtual-iot-device.js. Ключові функції:
● getSimulatedSensorData(): генерує імітовані дані температури та вологості.
7
● sendData(sensorId, valueType, value): формує JSON payload та надсилає його на серверний API за допомогою axios.post(). Обробляє відповіді та помилки.

// Фрагмент з virtual-iot-device.js (надсилання даних)
async function sendData(sensorId, valueType, value) {
const payload = { sensor_id: sensorId, value_type: valueType, value: value };
try {
const response = await axios.post(SERVER_URL, payload, { /* ... headers ... */ });
console.log(`Server response for ${valueType}: ${response.status} - ${JSON.stringify(response.data)}`);
} catch (error) { /* ... обробка помилок ... */ }
}
8. Налаштування віртуального IoT пристрою здійснюється через константи:
● SERVER_URL: адреса та ендпоінт серверного API.
● SENSOR_ID: унікальний ідентифікатор віртуального датчика.
● SEND_INTERVAL_MS: іІнтервал у мілісекундах, з яким пристрій надсилає дані.

3.7 Контрольні запитання
1) За якою програмною архітектурою побудована IoT/Smart Device частина програмної системи? IoT/Smart Device частина програмної системи "HoneyTrack", реалізована як віртуальний пристрій, побудована за модульною програмною архітектурою. Вона складається з логічних компонентів: модуля конфігурації, модуля симуляції даних датчиків, комунікаційного модуля для взаємодії з API через HTTP, та головного керуючого модуля, що організовує їх періодичну роботу.
2) Які програмні технології та компоненти використовуються в IoT/Smart Device частині програмної системи? У віртуальній IoT/Smart Device частині системи використовуються такі програмні технології та компоненти: платформа виконання Node.js, мова програмування JavaScript (ES6+), бібліотека axios для здійснення HTTP POST запитів до серверного API, а також вбудовані можливості JavaScript для генерації псевдовипадкових даних та формування JSON об'єктів.

3) Яка бізнес логіка реалізована в IoT/Smart Device частині системи? Бізнес-логіка, реалізована в IoT/Smart Device частині системи, включає періодичну симуляцію збору даних про температуру та вологість, формування з цих даних JSON повідомлень у встановленому форматі та їх автоматичне надсилання на визначений ендпоінт серверного API для подальшої обробки та зберігання.
4) Які ефективні математичні методи обробки користувацьких даних реалізовані у IoT/Smart Device частині системи? Ефективні математичні методи обробки даних, реалізовані безпосередньо у віртуальній IoT/Smart Device частині, обмежуються генерацією псевдовипадкових чисел за допомогою Math.random() для імітації показників датчиків та арифметичними операціями для внесення невеликих коливань у ці значення, щоб симулювати більш реалістичну поведінку. Складна математична обробка чи аналіз даних на самому пристрої не відбувається.
5) Які актори та які варіанти використання представлені на діаграмі використання (прецедентів) IoT/Smart Device частини програмної системи? На діаграмі прецедентів для IoT/Smart Device частини основним актором є сам "IoT-пристрій (Віртуальний)". Варіанти використання включають: "Ініціалізувати конфігурацію", "Згенерувати дані датчика" (що взаємодіє з імітованим "Датчиком"), "Сформувати JSON повідомлення", "Надіслати дані на сервер" (що взаємодіє з "Мережевим інтерфейсом" та "Сервером API") та "Запланувати наступне надсилання".
6) Як в IoT/Smart Device частині програмної системи здійснюється захист персональних даних? Оскільки віртуальний IoT-пристрій у поточній реалізації не обробляє та не зберігає персональні дані користувачів безпосередньо (він лише надсилає дані датчиків, асоційовані з sensor_id), специфічні заходи захисту персональних даних на самому пристрої мінімальні. Безпека передачі даних залежить від конфігурації серверного API (використання HTTPS) та потенційної аутентифікації пристрою.
7) Як IoT/Smart Device частина програмної системи взаємодіє з іншими компонентами програмної системи? IoT/Smart Device частина програмної системи взаємодіє з серверною частиною (бек-ендом) шляхом надсилання HTTP POST запитів на визначений REST API ендпоінт (/api/sensor-readings). Дані передаються у форматі JSON і

8) Як в IoT/Smart Device частині програмної системи забезпечується інтернаціоналізація? Інтернаціоналізація в IoT/Smart Device частині програмної системи не забезпечується.
9) Яка функціональність для налаштування та адміністрування реалізована у IoT/Smart Device частині програмної системи? Функціональність для налаштування віртуального IoT/Smart Device реалізована через константи, визначені безпосередньо у вихідному коді скрипта (virtual-iot-device.js). До них належать URL серверного API, унікальний ідентифікатор датчика (SENSOR_ID) та інтервал надсилання даних (SEND_INTERVAL_MS). Адміністрування пристрою зводиться до запуску та зупинки скрипта, а також моніторингу його консольних логів.
