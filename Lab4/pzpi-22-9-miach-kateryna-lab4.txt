4.2 Хід роботи
1. Веб-частина побудована на компонентній архітектурі React.js. Ключові шари включають: представлення (React-компоненти сторінок та UI-елементів), навігацію (клієнтський роутинг за допомогою react-router-dom), управління станом (React Context для глобального стану аутентифікації та локальний стан компонентів), взаємодію з API (сервісний шар з axios) та інтернаціоналізацію (i18next).
Приклад структури головного компонента App.js з роутингом та контекстом:
// client/src/App.js (фрагмент)
export const AuthContext = React.createContext(null);
function App() {
const [authState, setAuthState] = React.useState(/*...*/);
const setAuthData = (data) => { /*...*/ };
const logout = () => { /*...*/ };
return (
<AuthContext.Provider value={{ authState, setAuthData, logout }}>
<Router>
<nav> {/* ... Навігація з NavLink ... */} </nav>
<div className="page-container">
<Routes>
<Route path="/login" element={<LoginPage />} />
{/* ... інші публічні роути ... */}
<Route element={<ProtectedRoute />}> {/* Захист роутів */}
<Route path="/" element={<DashboardPage />} />
{/* ... інші захищені роути ... */}
</Route>
<Route element={<AdminRoute />}> {/* Адмінські роути */}
<Route path="/admin/users" element={<AdminUsersPage />} />
</Route>
</Routes>
</div>
</Router>
</AuthContext.Provider>
);
}
2. Основні технології: React.js, JavaScript (ES6+), react-router-dom для навігації, axios для HTTP-запитів, i18next та react-i18next для інтернаціоналізації, HTML5, CSS3. Управління залежностями здійснюється через npm, збірка – за допомогою інструментів Create React App (Webpack).
3. Веб-клієнт дозволяє користувачам реєструватися, входити в систему, управляти партіями меду (CRUD), місцями зберігання, налаштовувати сповіщення для датчиків та переглядати їх. Адміністратори мають доступ до управління користувачами (перегляд, зміна ролі, статусу).
Приклад виклику сервісу для створення партії меду в HoneyBatchesPage.js:
// client/src/pages/HoneyBatchesPage.js (фрагмент handleSubmit)
const handleFormSubmit = async (batchData) => {
try {
if (editingBatch) {

await createHoneyBatch(batchData);

};
4. Захист реалізовано через JWT-аутентифікацію: токен зберігається в localStorage та автоматично додається до всіх API-запитів за допомогою axios interceptor. Клієнтський роутинг використовує компоненти ProtectedRoute та AdminRoute для розмежування доступу до сторінок на основі наявності токена та ролі користувача.
Приклад axios interceptor для додавання токена (client/src/services/api.js):
// client/src/services/api.js (фрагмент)
apiClient.interceptors.request.use(
(config) => {
const token = localStorage.getItem('token');
if (token) {
config.headers['Authorization'] = `Bearer ${token}`;
}
return config;
}, /* ... */
);
5. Веб-клієнт взаємодіє виключно з серверною частиною (бекендом) через REST API. Надсилаються HTTP-запити (GET, POST, PUT, DELETE) на ендпоінти бекенду, дані передаються у форматі JSON.
6. Інтернаціоналізація реалізована за допомогою i18next та react-i18next. Створено файли перекладів (locales/uk/translation.json,
locales/en/translation.json) та файл конфігурації i18n.js. Хук useTranslation використовується в компонентах для отримання перекладених рядків.
Приклад використання useTranslation у компоненті:
// client/src/pages/LoginPage.js (фрагмент)
import { useTranslation } from 'react-i18next';
function LoginPage() {
const { t } = useTranslation();
return ( <h2>{t('loginPage.title')}</h2> /* ... */ );
}
7. Система підтримує дві мови: українську (uk, за замовчуванням) та англійську (en). Користувач може перемикати мову за допомогою кнопок в навігаційній панелі. Форматування дат та часу здійснюється з урахуванням поточної обраної локалі за допомогою new Date().toLocaleString(i18n.language).
Приклад перемикача мов в App.js:

8. Налаштування для користувача: зміна мови інтерфейсу, управління індивідуальними налаштуваннями сповіщень для датчиків (встановлення порогів).
Адміністрування (для ROLE_ADMIN):
● Перегляд списку всіх користувачів системи.
● Зміна ролі користувача (ROLE_USER / ROLE_ADMIN).
● Зміна статусу активності користувача (активувати/деактивувати).

9. Система "HoneyTrack" дозволяє користувачам отримувати сповіщення про відхилення параметрів зберігання меду. Користувачі можуть індивідуально налаштовувати порогові значення температури та вологості для датчиків через веб-інтерфейс. Ці налаштування зберігаються в базі даних (NotificationSettings).
Рисунок 4.1 – Налаштування порогів сповіщень користувачем
Коли IoT-пристрій надсилає нові дані (наприклад, температуру 21.9°C), серверна частина (sensorReadingService.js) автоматично порівнює їх з персональними налаштуваннями кожного користувача, який "підписаний" на сповіщення від цього датчика. Якщо значення виходить за встановлені межі, генерується запис у таблиці Alerts для відповідного користувача.
// Фрагмент логіки генерації сповіщень на сервері (sensorReadingService.js)
const activeSettings = await NotificationSetting.findAll({ where: { sensor_id, type, is_enabled: true }, include: [User] });
for (const setting of activeSettings) {
if ((setting.min_threshold && value < setting.min_threshold) || (setting.max_threshold && value > setting.max_threshold)) {
await alertService.createAlert({ user_id: setting.user.user_id, sensor_id, message: `Увага! ${type} (${value}) для датчика "${sensorName}" поза нормою (${setting.min_threshold}-${setting.max_threshold}).` });
}
}
Ці сповіщення потім відображаються на Дашборді користувача, інформуючи його про потенційні проблеми.

4.3 Висновки
У ході виконання лабораторної роботи було розроблено клієнтську частину програмної системи «HoneyTrack» на основі сучасної компонентної архітектури з використанням React.js. Реалізовано механізми маршрутизації, автентифікації та авторизації, управління глобальним станом додатка, підтримку мультимовного інтерфейсу, а також взаємодію з REST API для обробки даних. Система забезпечує повноцінний веб-інтерфейс для користувачів та адміністраторів, включаючи реєстрацію,
управління партіями меду, налаштування сповіщень і перегляд тривог. Завдяки реалізованим засобам інтернаціоналізації, інтерфейс доступний як українською, так і англійською мовами.
4.4 Контрольні запитання
1) За якою програмною архітектурою побудована веб частина програмної системи? Програмна архітектура веб-частини системи "HoneyTrack" реалізована як Односторінковий Додаток (SPA), розроблений з використанням бібліотеки React.js. Ця архітектура базується на компонентному підході, де користувацький інтерфейс розбитий на незалежні та перевикористовувані компоненти. Ключові шари включають шар представлення (React-компоненти сторінок та UI-елементів), шар навігації (клієнтський роутинг за допомогою react-router-dom), шар управління станом (React Context для глобального стану аутентифікації та локальний стан компонентів), шар взаємодії з API (сервісний шар з axios для HTTP-запитів до REST API бекенду) та шар інтернаціоналізації (з i18next та react-i18next).
2) Які програмні технології та компоненти використовуються в веб частині програмної системи? У веб-частині програмної системи використовуються такі основні програмні технології та компоненти: бібліотека React.js для побудови користувацького інтерфейсу, мова програмування JavaScript (ES6+), бібліотека react-router-dom для реалізації навігації на стороні клієнта, бібліотека axios для здійснення HTTP-запитів до серверного API, бібліотеки i18next та react-i18next для забезпечення інтернаціоналізації та локалізації. Верстка виконана з використанням HTML5 та CSS3, а управління залежностями та збірка проєкту здійснюються за допомогою npm (або yarn) та інструментів Create React App (Webpack).
3) Яка бізнес логіка програмної системи доступна у веб частині системи? У веб-частині системи доступна наступна бізнес-логіка: користувачі можуть проходити процедури реєстрації та автентифікації; після входу їм доступний дашборд з оглядовою інформацією та сповіщеннями. Основний функціонал включає управління партіями меду (створення, перегляд списку, редагування, видалення, експорт у CSV), управління місцями зберігання (створення, перегляд, редагування, видалення) та налаштування індивідуальних порогів для сповіщень від IoT-датчиків. Для користувачів з роллю адміністратора доступний функціонал управління користувачами системи (перегляд списку, зміна ролі, активація/деактивація акаунтів).
4) Які актори та які варіанти використання представлені на діаграмі використання (прецедентів) веб частини програмної системи? На діаграмі прецедентів веб-частини програмної системи основними акторами є "Пасічник (Користувач)" та "Адміністратор", причому Адміністратор успадковує всі можливості звичайного Користувача. Для Користувача доступні варіанти використання, такі як "Увійти в систему", "Зареєструватися", "Переглянути Дашборд", "Керувати партіями меду", "Керувати місцями зберігання", "Керувати IoT-датчиками" (базово), "Налаштовувати сповіщення" та "Змінити мову інтерфейсу". Для Адміністратора додатково доступні прецеденти "Управляти користувачами системи" (що включає перегляд списку, зміну ролі, зміну статусу активності) та потенційно "Ініціювати резервне копіювання даних" чи "Переглянути системні логи".
5) Як у веб частині програмної системи здійснюється захист персональних даних? Захист персональних даних у веб-частині програмної системи здійснюється шляхом використання JWT (JSON
Web Tokens) для аутентифікації: після успішного входу токен зберігається в localStorage браузера та автоматично додається до заголовка Authorization всіх захищених API-запитів за допомогою axios interceptor. Клієнтський роутинг використовує спеціальні компоненти-обгортки (ProtectedRoute, AdminRoute) для перевірки наявності валідного токена та відповідної ролі користувача перед наданням доступу до захищених сторінок.
6) Як веб частина програмної системи взаємодіє з іншими компонентами програмної системи? Веб-частина програмної системи взаємодіє виключно з серверною частиною (бекендом). Ця взаємодія відбувається через REST API за протоколом HTTP(S). Фронтенд надсилає асинхронні запити (GET, POST, PUT, DELETE) на відповідні ендпоінти API бекенду, передаючи дані у форматі JSON (у тілі запиту або як параметри URL) та отримуючи відповіді також у форматі JSON. Бекенд вже обробляє всю логіку взаємодії з базою даних та IoT-пристроями.
7) Як у веб частині програмної системи забезпечується інтернаціоналізація? У веб-частині програмної системи інтернаціоналізація (i18n) забезпечується за допомогою бібліотек i18next та react-i18next. Створено файли перекладів у форматі JSON для підтримуваних мов (наприклад, uk/translation.json, en/translation.json), які містять ключі та відповідні їм перекладені текстові рядки. Хук useTranslation використовується в React-компонентах для доступу до функції перекладу t() та екземпляра i18n для управління мовою.
8) Які варіанти локалізації реалізовані у веб частині програмної системи? Реалізовано два варіанти локалізації у веб-частині програмної системи: українська (встановлена як мова за замовчуванням та мова "фолбеку") та англійська. Користувач має
можливість перемикати мову інтерфейсу за допомогою відповідних кнопок у навігаційній панелі. Форматування дат та часу для відображення користувачеві здійснюється з урахуванням поточної обраної локалі (i18n.language) за допомогою стандартних методів JavaScript, таких як Date.prototype.toLocaleString().
9) Яка функціональність для налаштування та адміністрування програмної системи реалізована у веб частині програмної системи? У веб-частині програмної системи реалізована наступна функціональність для налаштування та адміністрування: користувачі можуть налаштовувати мову інтерфейсу та індивідуальні пороги для отримання сповіщень від датчиків. Для користувачів з роллю адміністратора доступна окрема сторінка "Управління користувачами", де вони можуть переглядати список всіх зареєстрованих користувачів, змінювати їхні ролі (наприклад, з ROLE_USER на ROLE_ADMIN і навпаки) та активувати або деактивувати облікові записи користувачів.
